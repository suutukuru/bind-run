# 用語集

| 用語 | 初心者向けの説明 | このゲームでの例 |
|---|---|---|
| ゲームループ | 「入力を読む → 状態を更新 → 描画」を 1 秒に何十回も繰り返す仕組み | 毎フレーム、キャラを動かし、紐で位置を補正し、線を描く |
| フレーム / フレームレート（FPS） | 1 回分の更新・描画 / 1 秒あたりの回数 | 目標 60fps（NFR-001） |
| デルタタイム（delta） | 前のフレームからの経過秒数。速度 × delta で移動量を出すと端末差が出ない | `_physics_process(delta)` |
| 物理フレーム | 物理計算用に固定間隔（既定 60 回/秒）で呼ばれる更新 | 移動・拘束・当たり判定は `_physics_process` で行う |
| ベクトル（Vector2） | 向きと大きさを持つ量。2D では (x, y) | `move_intent`、キャラの位置 |
| 正規化 | ベクトルの向きを保ったまま長さを 1 にすること | ハブから見たキャラの向きを求め、最大半径を掛けて位置を補正 |
| シーン | ノードを組み合わせた再利用可能な部品。`.tscn` ファイル | `Character.tscn` を A と B の 2 つに使う |
| ノード | Godot の最小部品。木構造に並べる | `CharacterBody2D`, `Camera2D` |
| リソース（Resource） | データの入れ物。`.tres` で保存し、エディタで編集できる | `RopeConfig` に紐の長さを持たせる |
| CharacterBody2D | コードで速度を決めて動かす物理ボディ | A と B |
| RigidBody2D | 力や重力で物理エンジンが動かすボディ | 紐やキャラには使わない（ADR-003, 004） |
| 衝突判定 | 物体同士が重なったか・当たったかを調べること | 敵とキャラの接触、紐と敵の接触 |
| ヒットボックス | 攻撃や被弾を判定するための見えない形 | 紐攻撃では「線分」がヒットボックス |
| 拘束（コンストレイント） | 「この距離より離れない」などの条件を満たすよう位置を直す処理 | 最大長を超えたらハブ方向へ戻す |
| ハブ（接続点） | 本プロジェクトの用語。2 人の紐が集まる点。全員の位置の平均で計算 | A と B の中点 |
| 伸び率 | 本プロジェクトの用語。0 = たるみ、1 = 伸びきり | 紐の色、紐攻撃の条件 |
| シグナル | 「何かが起きた」ことを通知する仕組み。Web のイベントに近い | 敵の `died` シグナルで経験値を出す |
| headless | 画面を出さずにプログラムを動かすモード | 自動テストの実行 |
| 単体テスト | 関数 1 つなど小さな単位を自動で確かめるテスト | `RopeModel.constrain()` のテスト |
| プロトタイプ | 仕組みや面白さを確かめるための試作品。見た目は後回し | Phase 1〜2 |
| スパイク | 不確実な点だけを素早く確かめる使い捨ての試作 | Phase 2b のスマホ操作確認 |
| ローグライト | 1 プレイごとにリセットされる成長と、ランダムな選択を楽しむジャンル | レベルアップの 3 択強化 |
| project.godot | Godot プロジェクトの設定ファイル。名前、起動シーン、画面サイズ、入力、描画方式などが入る。Web で言えば package.json に近い | `run/main_scene` で `main.tscn` を起動シーンに指定 |
| レンダラー | 画面に絵を描く仕組み。Godot 4 は Forward+ / Mobile / Compatibility の 3 種 | 2D 中心なので最も軽い Compatibility（ADR-010） |
| ストレッチモード | ウィンドウの大きさが変わったときに画面をどう伸縮するかの設定 | `canvas_items` + `expand`（ウィンドウが広ければ見える範囲が広がる） |
